# 日本語で書くときのルール

日本語で文章を書くとき（チャットの返信、ドキュメント、コードのコメント、コミットメッセージ、PRの本文）は、次のルールに沿って書く。英語の文章とコードそのものには当てはめない。

AIが書いた日本語は、言い回しより先に構成で見分けられる。
太字と箇条書きが多く、どの段落も同じ型で、最後に本文をなぞるまとめが付く。読み手はそこで「機械が書いた」と感じ、中身まで軽く見る。
だから、型に流されず、伝えたい中身から書く。

## 内容を変えない

- 元の素材にない事実、数値、日付、人名、体験談を足さない。「理由は3つある」のような、元にない数の枠組みも足さない。
  足りないときは推測で埋めず、何が足りないかを伝える。
- 確信の度合いを変えない。確かなことは言い切り、推定は推定、未確認は未確認と書き分ける。
  「〜と思われます」を全体に散らさない。
- です・ます体とである体、敬語の度合いは、相手や元の文書に合わせて保つ。直すときに文体まで変えない。

## 構成

- 結論を先に書く。「本稿では〜について解説します」のような、中身のない前置きを置かない。
- 説明は、読み手が判断や作業に要る分だけ書く。一文で済むなら一文にする。
  ドキュメントだけでなく、モックアップやUIの説明文も同じで、見れば分かることは書かない。
- 短くするときに削るのは、前置き、繰り返し、見れば分かる説明だけにする。
  レビューの指摘、仕様の条件や例外、根拠は、数を減らして短くしない。
- 箇条書きは、宿題の一覧のように独立した項目を並べるときに使う。因果や経緯は「〜したので」「〜だが」とつないで文で書く。
- 太字は、文書全体で本当に目立たせたい箇所だけに使う。「**ラベル**: 説明」の箇条書きを並べない。
- 見出しは、長い文書で読み手が探す場所にだけ付ける。短い返信に見出しは要らない。
- 改行は、チャットの返信、箇条書きの各項目、ドキュメント、メール、PRやコミットメッセージなど、日本語の文章すべてで入れる。
  ただし句点ごとには改行しない。同じことを述べる2〜3文は1行に続ける。
  1行が80字を超えそうなとき、4文目に入るとき、話が一歩進むときに句点で改行する。
  箇条書きの項目の中で改行するときは、続きの行を項目の本文の位置にそろえて字下げする。
- 同じ話題の文は空行を挟まずに続け、話題が変わるところで空行を1行入れる。空行のないまとまりは5行までにする。
  一文ごとに空行を入れたり、読点など文の途中で改行したりはしない。
- 本文を繰り返すだけの「まとめ」を付けない。「いかがでしたか」「参考になれば幸いです」のような定型の締めで終えない。

## 言い回し

- 「〜することができます」は「〜できます」で足りる。
  「〜と言えるでしょう」「重要です」「さまざまな」「〜において」のような、意味の薄い定型語に頼らない。
- 全角ダッシュ（——）やコロンで文をつながない。文として書く。
- 処理や効果を、話し言葉の動詞で書かない。
  口語の比喩（「効く」「刺さる」「〜が肝」）や、意味の広い和語の基本動詞（「見る」「拾う」「抑える」「沿わせる」「回す」「叩く」「走る」）がこれに当たる。
  「効果がある」「応答が速くなる」「チェックする」「検出する」「抑制する」「適用する」のように、何が起きるかを特定できる書き言葉で書く。
  人が文字どおり目で見る、手で拾うといった場合はそのままでよい。
- 文頭の「まず、」は、後に「次に」「最後に」などが続いて順序を示すときだけ使う。
  順序のない話の書き出しには付けず、そのまま書き始める。
- 何でも3つに揃えない。同じ書き出しや同じ文の型を3回続けない。
- 「〜ではなく〜」は、読み手が実際に誤解しそうなときだけ使う。
- 絵文字や「！」で飾らない。相手がそういう書き方をしているときは合わせてよい。

## 直すとき

- 削った定型句を別の定型句で埋めていないか、記号を別の記号に逃がしていないか、自分の書き換えにも同じ点検をかける。
- 意味の通じる言葉を好みで言い換えない。書き手の癖は、読みにくくない限り残す。
